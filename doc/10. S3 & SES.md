# ☁️ AWS Core Module & Authentication System

본 프로젝트는 **AWS S3**를 활용한 이미지 업로드 기능과 **AWS SES**를 활용한 이메일 인증 시스템이 통합되어 있습니다.
보안을 위해 **Keyless (IAM Role 기반)** 인증 방식을 채택하였으며, 회원가입 시 **Redis**를 활용한 이메일 인증 절차가 수행됩니다.

## 🛠️ 주요 기능 (Key Features)

### 1. AWS Infrastructure Integration (`AwsModule`)
* **AWS S3 (Simple Storage Service):** * 식당, 메뉴, 카테고리, 유저 프로필 등의 이미지 자산 저장.
  * `uuid`를 이용한 파일명 난수화로 중복 방지.
* **AWS SES (Simple Email Service):** * 회원가입 시 인증 메일 발송.
* **Security (Keyless Auth):** * Access Key를 코드에 하드코딩하지 않습니다.
  * 실행 환경(Local/ECS)의 자격 증명을 자동으로 로드하는 `CredentialProviderChain` 패턴을 적용했습니다.

### 2. Email Verification Flow
1. **회원가입 요청:** 유저 생성 (`verified: false`) 및 인증 토큰(UUID) 생성.
2. **토큰 저장:** **Redis**에 `email-verify:{token}` 키로 저장 (TTL: 5분).
3. **이메일 발송:** AWS SES를 통해 인증 링크 전송.
4. **인증 완료:** 링크 클릭 시 Redis 토큰 검증 후 계정 활성화 (`verified: true`) 및 토큰 삭제.

## ⚙️ 환경 설정 (Configuration)

이 모듈을 정상적으로 실행하기 위해서는 환경 변수 및 AWS 권한 설정이 필수적입니다.

### 1. `.env` 파일 설정

```bash
# AWS Common
AWS_REGION=ap-northeast-2           # 서울 리전

# AWS S3 (이미지 업로드 버킷)
AWS_S3_BUCKET_NAME=coupang-eats-uploads-prod

# AWS SES (이메일 발송)
# [주의] SES Sandbox 모드일 경우, AWS 콘솔에서 인증된 이메일만 사용 가능
AWS_SES_SENDER_EMAIL=jx7789@naver.com
```

### 2. AWS IAM Policy (권한 정책)

서버(ECS Task Role) 또는 로컬 개발자(User)에게 아래 권한이 반드시 부여되어야 합니다.

#### 🅰️ S3 정책 (`NestJS-S3-Policy`)
식당, 메뉴, 카테고리 등 서비스 전반의 업로드 경로(`resource`)를 허용해야 합니다.

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "ListBucket",
            "Effect": "Allow",
            "Action": "s3:ListBucket",
            "Resource": "arn:aws:s3:::coupang-eats-uploads-prod"
        },
        {
            "Sid": "ObjectReadWriteDelete",
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:GetObject",
                "s3:DeleteObject",
                "s3:PutObjectAcl"
            ],
            "Resource": [
                "arn:aws:s3:::coupang-eats-uploads-prod/users/*",
                "arn:aws:s3:::coupang-eats-uploads-prod/restaurant/*",
                "arn:aws:s3:::coupang-eats-uploads-prod/dish/*",
                "arn:aws:s3:::coupang-eats-uploads-prod/category/*"
            ]
        }
    ]
}
```

#### 🅱️ SES 정책 (`NestJS-SES-Policy`)
지정된 발신자 주소(`AWS_SES_SENDER_EMAIL`)로만 메일을 보낼 수 있도록 제한하여 보안을 강화합니다.

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ses:SendEmail",
                "ses:SendRawEmail"
            ],
            "Resource": "*",
            "Condition": {
                "StringEquals": {
                    "ses:FromAddress": "jx7789@naver.com"
                }
            }
        }
    ]
}
```

## 🚀 개발 환경 가이드 (Local Development)

본 프로젝트는 **Keyless** 방식이므로 코드 내에 Access Key가 없습니다. 
로컬(Mac/Windows) 환경은 IAM Role을 직접 사용할 수 없으므로, **개발자 본인의 AWS 자격 증명을 주입**해야 합니다.

### 방법 1. AWS CLI 설정 (권장)
터미널에서 아래 명령어를 실행하여 로컬 프로필을 생성합니다.
```bash
$ aws configure
AWS Access Key ID [None]: <YOUR_ACCESS_KEY>
AWS Secret Access Key [None]: <YOUR_SECRET_KEY>
Default region name [None]: ap-northeast-2
```

### 방법 2. 환경 변수 주입 (임시 테스트용)
터미널 세션에 일시적으로 키를 주입하여 실행합니다.
```bash
export AWS_ACCESS_KEY_ID=<YOUR_KEY>
export AWS_SECRET_ACCESS_KEY=<YOUR_SECRET>
npm run start:dev
```

## 🚨 트러블슈팅 (Troubleshooting)

자주 발생하는 에러와 해결 방법입니다.

### Q1. `CredentialsProviderError: Could not load credentials...`
* **원인:** 로컬 컴퓨터에서 AWS 자격 증명을 찾지 못했습니다. (Keyless 코드의 특징)
* **해결:** 위 **[개발 환경 가이드]**를 참고하여 `aws configure`를 수행하거나 환경 변수를 설정하세요.

### Q2. `MessageRejected: Email address is not verified`
* **원인:** AWS SES 계정이 **Sandbox(샌드박스)** 모드입니다.
* **해결:** 1. Sandbox 모드에서는 **보내는 사람**뿐만 아니라 **받는 사람(수신자)**의 이메일도 AWS 콘솔에서 인증(Verify)되어야 합니다.
  2. 테스트 시 API 요청 Body의 `email` 값을 인증된 이메일(`jx7789@naver.com`)로 설정하세요.

### Q3. `AccessDenied` (S3 업로드 중)
* **원인:** IAM 정책의 `Resource` 경로에 해당 폴더 권한이 없습니다.
* **해결:** `NestJS-S3-Policy` JSON에서 `restaurant/*`, `dish/*`, `category/*` 경로가 포함되어 있는지 확인하세요.

### Q4. `UnknownDependenciesException` (의존성 에러)
* **원인:** 모듈 간 Import/Export 설정 누락.
* **체크리스트:**
  * `AuthModule` imports에 `NotificationModule`, `CacheModule` 추가.
  * `NotificationModule` imports에 `ConfigModule` 추가.
  * `CacheModule` exports에 `CacheService` 추가.
  * `CacheService` 주입 시 `@Inject(CacheServiceKey)` 사용 (커스텀 프로바이더).
